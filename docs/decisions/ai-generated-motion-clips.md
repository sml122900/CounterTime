# 기술 결정: AI 생성 모션 클립 (유도 전용 동작 4종)

작성 2026-08-07 · 상태: **적용 완료, Play 검증 전**

## Problem — 문제

08-05 에 노드↔모션 연결을 끝냈지만 **모션 자체가 유도가 아니었다.**

Mixamo 무료 라이브러리로 10개 상태를 채웠는데, 이 게임이 필요로 하는 동작이 거기 없다.

| 필요한 동작 | 08-05 에 붙인 것 | 문제 |
|---|---|---|
| 업어치기 진입 | `Standing Melee Punch` | 펀치는 던지기가 아니다 |
| 밭다리걸기 | `Standing Melee Punch` / `Jumping` | 다리 후리기가 아니다 |
| 던져져서 낙법 | `Stumble Backwards` / `Shoved Reaction With Spin` | 비틀거리는 것과 던져지는 것은 다르다 |
| 굳히기·조르기 (n17/n24/n25) | `Taunt` / `Standing Melee Punch` | **누워서 하는 동작인데 서 있는 모션이 붙어 있었다** |

마지막 줄이 특히 나빴다. 굳히기는 시나리오에서 승부가 갈리는 국면인데, 화면에서는 두 캐릭터가 서서 도발하고 있었다.

Mixamo 에는 격투기 일반 동작(펀치·킥·리액션)은 많지만 **유도 기술 모션은 없다.** 종목 순서가 유도 → 복싱 → 킥복싱 → MMA 인데, 첫 종목부터 라이브러리로 못 채운다는 뜻이었다.

## Action — 한 것

### 1. Mixamo 추가 탐색이 아니라 AI 생성

세 갈래였다.

| 선택지 | 비용 | 판단 |
|---|---|---|
| Mixamo 에서 더 찾기 | 무료 | **탈락** — 유도 기술 자체가 라이브러리에 없다. 더 뒤져도 "비슷한 것"만 나온다 |
| 모캡 촬영 | 장비·인력·시간 | **보류** — 프로토타입 단계에 맞지 않는 비용. 나중에 할 일 |
| AI 생성 | 5 크레딧 × 4 = **20 크레딧** | **채택** |

프로토타입 단계에서 필요한 건 "유도처럼 보이는 것"이지 경기 영상 수준의 정확도가 아니다. 20 크레딧으로 4개를 즉시 얻는 쪽이 맞았다.

생성한 4종은 **시나리오에서 반복 등장하는 동작만** 골랐다.

| 클립 | 붙는 노드 수 | 시전자 |
|---|---|---|
| `ai_ukemi_back` | 8 | A·B 양쪽 (던져지는 쪽) |
| `ai_ground_pin` | 10 | 주로 A, n41 만 B |
| `ai_seoinage_entry` | 4 | 항상 B |
| `ai_osotogari_entry` | 4 | 항상 A |

낙법과 굳히기가 압도적으로 자주 나온다 — 시나리오가 "던지고 → 굳히는" 구조라서 그렇다. 개별 기술(허리후리기·안오금띄기·감아치기·어깨로 매치기)마다 클립을 만들면 크레딧이 몇 배로 드는데, **당하는 쪽 모션은 기술이 뭐든 비슷하다.** 그래서 던지는 쪽만 주요 2종으로 좁히고 낙법은 공용으로 썼다.

### 2. 임시 대체를 명시적으로 허용 — 단, 기록을 남긴다

n10 은 **허리후리기**(하라이고시)인데 `ai_osotogari_entry`(밭다리)를 붙였다. 다른 기술이다.

붙인 이유는 08-05 에 거기 `Jumping` 이 들어가 있었기 때문이다. 점프보다는 다리 후리기가 낫다 — **틀린 유도 기술이 안 유도 기술보다는 가깝다.**

대신 이걸 "해결"로 기록하지 않았다. STATUS.md 에 `알려진 공백` 섹션을 새로 만들어 넣었다.

```
n10 허리후리기 = ai_osotogari_entry 임시 대체. 기술 상이(하라이고시 ≠ 오소토가리), 모캡 대상
```

임시 대체를 허용하되 **임시라는 사실이 사라지지 않게** 하는 것이 요점이다. 이런 건 기록이 없으면 6개월 뒤에 "왜 허리후리기에 밭다리 모션이 붙어 있지"가 된다.

### 3. `.anim` 은 LFS 로 보내지 않았다

클립 4개가 각 5.7MB, 합 23MB다. 그런데 `.gitattributes` 에서 `.anim` 은 LFS 가 아니라 `text eol=lf` 로 잡혀 있다.

**그대로 뒀다.**

- `.anim` 은 바이너리가 아니라 YAML 텍스트다. 실수 커브 데이터라 zlib 압축이 잘 먹는다 — 23MB 가 pack 에서 수 MB 수준으로 떨어진다
- 텍스트로 두면 diff 가 된다. 클립 설정(Loop, 이름)을 고칠 때 무엇이 바뀌었는지 보인다
- LFS 는 08-03 에 이미 배운 게 있다 — 나중에 붙이면 소급되지 않는다(`docs/troubleshooting/lfs-after-first-commit.md`). 지금 굳이 옮길 이유가 없으면 안 옮기는 게 맞다

**단, 조건부다.** AI 클립을 여러 번 재생성해 덮어쓸 계획이면 매번 223,739줄짜리 blob 이 새로 쌓인다. 재생성 빈도가 높아지면 그때 `*.anim` 을 LFS 로 옮기는 게 맞다. 지금은 아니다.

### 4. 생성 부산물은 저장소 밖으로

- `Assets/AI Toolkit/` — 패키지 캐시. Unity 가 재생성한다
- `GeneratedAssets/` — 생성 중간산물. 하위 폴더 이름이 전부 클립 guid 였다 (`b3b76699…`, `…_deleted` 포함)

둘 다 `.gitignore` 로 보냈다. 규칙을 **파일 맨 끝에** 붙여야 했던 이유는 별도 문서에 — `docs/troubleshooting/unity-asset-commit-boundary.md`

### 검토했다가 안 택한 것

- **기술마다 클립 1개씩 생성** — 시나리오에 나오는 유도 기술은 허리후리기·안오금띄기·안뒤축 감아치기·어깨로 매치기까지 최소 8종이다. 40 크레딧 이상 들고, 대부분 노드 1~2개에만 쓰인다. 자주 나오는 4종부터 확인하고 늘리는 쪽이 맞다
- **n18/n20/n26/n28 도 굳히기 클립으로 교체** — 승패가 확정된 종료 화면이다. `Victory Idle` / `Dying` / `Defeated` 가 승부 결과를 더 잘 보여준다. 굳히기 자세로 통일하면 "이겼다"가 안 보인다

## Result — 결과

- 19개 노드 · 25개 State 교체. `NodeMotionMap.asset` 25 insertions / 25 deletions (줄 수 변화 없음, 문자열만)
- 4개 State 가 `AC_Fighter_A/B` 양쪽에 다 있는 것을 확인 — A/B 어느 쪽에 배정해도 CrossFade 대상이 존재한다
- 08-05 에 남긴 공백 *"굳히기·조르기 국면에 마땅한 클립이 없어 Taunt/Punch 로 때웠다"* 해소
- **Play 검증은 0.** 파일 레벨에서만 확인했다

### 생성 에셋은 프로젝트 컨벤션을 물려받지 않는다

문서를 쓰면서 `.anim` / `.controller` 를 읽다가 발견했다. **4개 클립 전부 Loop ON 이고 8개 State 전부 나가는 트랜지션이 없었다.**

08-05 규칙(원샷은 Loop OFF + exitTime 0.9 자동 복귀 / 유지는 트랜지션 없음)에 비추면 `ai_ground_pin` 만 맞고 나머지 셋은 어긋났다. 업어치기 진입과 낙법은 원샷인데 유지로 설정돼 있었다 — 무한 반복된다.

생성 도구는 클립을 만들고 State 까지 넣어주지만 **Loop 정책도 전이 규칙도 모른다.** Mixamo 클립을 받았을 때는 사람이 하나씩 설정하니 자연히 컨벤션이 적용됐는데, 생성 도구는 그 단계를 건너뛴다. 에셋 조달 경로가 바뀌면 **기존 컨벤션이 자동으로 따라오는지 별도로 확인해야 한다.**

수정은 MCP 로 Unity 에디터에서 했다 — `AnimationUtility.SetAnimationClipSettings` 로 Loop OFF, `AnimatorState.AddTransition` 으로 복귀 트랜지션. `.controller` YAML 을 손으로 고칠 수도 있지만 트랜지션은 별도 앵커를 가진 객체라 앵커를 직접 만들어야 하고, 에디터 API 를 쓰면 Unity 가 재직렬화해준다.

결과: 원샷 3종만 Loop OFF, 6개 State 에 트랜지션 추가. A 컨트롤러의 트랜지션 9개(기존 6 + 신규 3)가 전부 같은 파라미터, 같은 목적지(`Fight Idle`)다.

### 되돌리는 법

`NodeMotionMap.asset` 은 문자열 리스트다. 인스펙터에서 `stateA` / `stateB` 를 08-05 값으로 되돌리면 끝이고, 코드 변경은 없다. 되돌릴 값은 커밋 `7e776e0`("before AI clip mapping")에 그대로 있다 — 이 스냅샷을 남긴 이유가 이것이다.
