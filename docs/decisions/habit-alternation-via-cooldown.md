# 기술 결정: "두 갈래를 번갈아"를 무작위 대신 쿨다운 교대로 근사했다

작성 2026-08-13 · 상태: **적용 완료(근사, 한계 문서화)**

## Problem — 문제

ROSTER.md가 4강 임준철과 동메달전 오재훈 둘 다에 "두 기술을 번갈아 낸다"는
습관을 요구했다 — 임준철은 어깨매치기/발뒤축걸기, 오재훈은 허리후리기/
밭다리걸기. §D 예측 되치기(장래 단계) 설계 의도는 "어느 쪽을 낼지 읽으면
크게 받는다"는 진짜 2지선다다.

기존 `HabitDefinition`은 조건 하나에 액션 하나가 고정으로 묶인 불변
객체다. 하나의 습관이 발화 시점마다 다른 기술을 무작위로 고르게 하려면
`HabitAction`에 대안 슬롯을 추가하고, 그 슬롯 중 하나를 고르는 난수 소비를
`HabitLadder.Next`(모든 상대·모든 습관이 공유하는 코드) 안에 넣어야 한다 —
Brain 계층의 공유 인프라를 건드리는 변경이다.

## Action — 한 것

공유 인프라를 안 건드리고, 이미 있는 쿨다운 메커니즘(`MinTurnsBetweenFirings`,
`HabitState.IsOnCooldown`)만으로 근사했다. 같은 조건(그립 우세)을 가진 두
습관을 사다리에 나란히 두고 둘 다 쿨다운 2를 준다.

```csharp
case HabitId.ShoulderThrowOnGripEdge:
    return new HabitDefinition(id, ctx => ctx.OwnEffectiveGrip >= 1,
        new HabitAction(..., "어깨 매치기"), 0.60f, minTurnsBetweenFirings: 2);
case HabitId.HeelHookOnGripEdge:
    return new HabitDefinition(id, ctx => ctx.OwnEffectiveGrip >= 1,
        new HabitAction(..., "발뒤축걸기"), 0.60f, minTurnsBetweenFirings: 2);
```

쿨다운 계산(`Turn - last < MinTurnsBetweenFirings`)을 손으로 검산했다.
쿨다운이 정확히 2일 때: 어깨매치기가 턴 N에 발화하면, 턴 N+1엔
`(N+1)-N=1 < 2`라 쿨다운 중이라 사다리가 다음 습관(발뒤축걸기, 쿨다운
없음)으로 넘어가 발화한다. 턴 N+2엔 어깨매치기가 `(N+2)-N=2 < 2`가
거짓이라 다시 열리고, 발뒤축걸기는 `(N+2)-(N+1)=1 < 2`라 이번엔 막힌다 —
사다리 순서(어깨매치기가 먼저 나열됨)대로 어깨매치기가 다시 발화한다.
그립 우세가 매 턴 유지된다는 전제 아래 정확히 A-B-A-B가 나온다는 뜻이다.

## Result — 결과

`ImJunchul_AlternatesShoulderAndHeelHook_WhenGripStaysHigh` 테스트가 같은
`HabitState`에 `ladder.Next`를 네 번 연속 불러 어깨-발뒤축-어깨-발뒤축
순서를 그대로 확인한다. Play 모드 스모크에서도 임준철전이 40교환 안에
judgement 1건을 냈다 — 완전히 죽은 습관은 아님을 확인했다(단, 그립이
계속 우세를 유지하지 않는 실전에서는 엄격한 A-B-A-B가 안 보일 수 있다).

오재훈(`MixedBigThrowA`/`MixedBigThrowB`)도 같은 패턴을 재사용했다 — 새
메커니즘을 또 만들지 않고 검증된 것을 그대로 썼다.

## 면접 예상 질문

**"이게 진짜 50/50인가?"**
아니다. 그립 우세가 연속되는 동안에는 결정론적 A-B-A-B이고, 매 순간 독립
확률이 아니다. 그립이 끊겼다 다시 붙으면 어느 쪽 차례로 재개될지는 마지막
발화 시점의 쿨다운 잔여에 달려 있다 — 완전한 무작위보다 예측 가능성이
높다. ROSTER 문구("번갈아")가 애초에 alternation을 뜻하는지 random pick을
뜻하는지 자체가 자연어로 모호했고, "번갈아"라는 단어 자체가 alternation
쪽에 더 가깝다고 읽어 이 근사를 택했다 — 정확한 요구가 매 순간 50/50이라면
재설계가 필요하다.

**"왜 공유 인프라를 안 건드렸나?"**
`HabitAction`/`HabitLadder`는 진도윤을 포함한 모든 상대가 쓰는 코드다.
두 상대(임준철·오재훈)의 alternation 요구 하나 때문에 그 코드에 "발화
시점 대안 선택" 개념을 넣으면, 그 개념이 앞으로 다른 습관의 조건/발화
로직과 어떻게 상호작용하는지(쿨다운은 어느 쪽 기준으로 도는가, 관측
원장은 어느 기술로 기록되는가)까지 전부 다시 설계해야 한다. 이번 세션의
범위("습관만", 콤보·예측 되치기는 이월)에서 그 비용을 들일 근거가 없다고
판단했다.

## 말할 가치가 있는 지점

기존 메커니즘(쿨다운)의 부작용(순서를 밀어내는 성질)을 의도된 기능(교대
패턴)으로 재활용한 경우다 — 새 코드를 안 짜고 기존 코드가 이미 가진
성질을 계산으로 검증해서 썼다. 다만 이건 "우연히 맞아떨어진 편법"과
"의도한 설계"의 경계에 있는 선택이라, 문서화하지 않으면 다음 사람이
"왜 쿨다운이 하필 2인가"를 이해 못 한다 — 그래서 이 결정 문서와 코드
주석 양쪽에 계산 과정을 그대로 남겼다.
