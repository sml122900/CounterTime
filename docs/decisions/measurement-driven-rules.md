# 기술 결정: 게임 규칙을 계측으로 개정한다 — 읽어서가 아니라

작성 2026-08-10 · 상태: **적용 완료. `OPPONENT_BRAIN` 4회 · `MATCH_RULES` v3.4 개정**

## Problem — 문제

상대 브레인 3단계는 "사양서대로 구현"이 목표였다. `OPPONENT_BRAIN.md` 에 습관 3개, 읽기 사다리, 발화확률 0.75, 관측 3회 임계가 전부 숫자까지 적혀 있었다.

구현은 끝났고 테스트 145개가 초록이었다. 그런데 **그게 잘 도는지는 아무도 몰랐다.**

이 시스템은 확률과 상태가 얽혀 있어서 단위 테스트가 답할 수 없는 질문이 남는다.

- 한 경기 안에 관측 3회가 **실제로** 쌓이는가?
- 읽기 항이 실제로 얼마나 자주 0 이 아닌가?
- B 가 습관대로 두는가, 아니면 사실상 무작위인가?

각 규칙은 단위 테스트로 증명돼 있었다. **규칙들이 같이 굴러갔을 때 무슨 일이 나는지**가 공백이었다.

## Action — 한 일

### 1. 판정이 아니라 계측을 먼저 붙였다

헤드리스 스모크를 넣었다. A 커밋은 픽스처가 공급하고 B 는 브레인이 두는 경기를 50교환까지 굴린다. **숫자를 단언하지 않는다** — 0 이냐 아니냐 정도만 본다. 튜닝은 사람이 정한다.

찍는 것:

| 계측 | 무엇을 가른다 |
|---|---|
| 습관별 발화 횟수 · 확정 도달 시점 | 관측 3회가 한 경기 안에 가능한가 |
| 사다리 행별(1~6) 적중 횟수 | 읽기 시스템이 실제로 도는가 |
| 폴백 비율 | B 가 습관대로 두는가, 무작위인가 |
| 판정 등급 분포 · 득점자 A/B | 점수가 어디서 나는가 |
| 5교환마다의 양쪽 체력 | 무엇이 경기를 제한하는가 |
| 그쳐 횟수 | 회복이 실제로 도는가 |

첫 결과가 전제를 깨뜨렸다.

```
=== A varies (4-cycle) ===
  turns=33  fallback=29 (87.9%)
  ladder row 1: 0   row 2: 0   row 3: 0
  ladder row 4: 0   row 5: 0
  ladder row 6: 33            ← 전부 Neutral
```

**33교환 전부가 6행(Neutral).** 판정식에서 폭이 가장 큰 항(읽기 −3…+3)이 통째로 죽어 있었다. 에러는 하나도 안 났고 테스트는 전부 초록이었다.

### 2. 세 번의 개정 — 전부 숫자가 아니라 규칙

**(1) 습관 H4 `잡기 노림` 신설.** 원인은 관측될 습관이 없다는 것이었다. H1 은 잡기 우위가 조건인데 B 가 거기 못 닿고, H2 는 지도가 필요하고, H3 은 예비다. 초반 내내 조건이 서는 습관이 하나도 없으면 관측이 0 에서 안 움직인다.

H4 는 밸런스가 아니라 **구조물**이다. 셋을 동시에 푼다 — 관측이 쌓이는 첫 습관이 생기고, B 가 잡기를 다투므로 H1 조건이 도달 가능해지고, `MATCH_RULES §4.1` 카논 케이스 3("상대가 잡으러 오는 순간 틀어잡고 밭다리 = 7 = 한판")이 **플레이에서 재현 가능**해진다. 그 장면은 H4 없이는 도달 불가였다 — B 가 잡으러 오는 걸 읽을 방법이 없었다.

**(2) 폴백은 큰기술을 내지 않는다.** 계측에서 판정의 절반이 폴백에서 나왔다.

전제로 올렸다: **판정을 발화하는 수는 이유가 있는 수여야 하고, 브레인에서 이유는 습관이다.** 폴백은 정의상 고를 이유가 없는 턴이므로 거기서 나온 던지기는 아무도 읽을 수 없다. 읽을 수 없는 던지기가 절반이면 수싸움이 절반만 성립한다.

이 규칙이 사주는 성질이 목적이다 — **B 의 모든 큰기술이 습관에서 나온다 = 원리적으로 전부 읽을 수 있다.** 테스트 이름이 그걸 말한다: `EveryBigThrowByB_ComesFromAHabit`.

**(3) `MATCH_RULES` v3.4 — 득점 후 그쳐.** 체력 궤적을 찍고 나온 것이다.

```
stamina: [0] A100/B100  [10] A65/B74  [20] A26/B39  [end] A1/B5
```

교환당 3~4 선형, 약 30교환에 바닥. 그런데 §2 는 "시퀀스 6~8개 × 30~60초"를 상정하고 교환 3~5초로 환산하면 **60~80교환**이 나와야 한다. **§2 와 §5 가 서로 다른 경기를 기술하고 있었다.**

원인은 회복이 그쳐에 묶여 있는데 그쳐를 만드는 규칙이 지도와 위장뿐이라는 것이었다 — 실측 그쳐가 경기당 0~2회. §5.3 의 +3 이 사실상 도달 불가였다.

이건 **A 의 공격 빈도와 무관한 규칙 구멍**이다. 누가 A 를 잡든 §2 와 §5 는 안 맞는다. 그래서 "경기 길이 판단은 6단계로 미룬다"는 결정과 충돌하지 않는다.

### 3. 개정마다 근거 수치를 문서에 박았다

숫자를 고친 게 아니라 **왜 고쳤는지를 규칙 문서에 넣었다.** 예:

> H1 fired **11 times in 27 exchanges** — that is not a habit, it is a compulsion.
> Nobody throws every single turn they hold a grip edge, and from the reading side
> a signal that appears every turn carries no information to read.

이렇게 적어두면 다음 사람이 쿨다운 3 을 보고 "왜 3인가"를 다시 묻지 않는다. 그리고 나중에 수치가 달라졌을 때 **그 근거가 아직 유효한지**를 판단할 수 있다.

## Result — 결과

### 읽기 시스템이 살아났다 (현실적 A 프로필)

| | 최초 | 최종 |
|---|---|---|
| 사다리 1~5행 | **0회** | **11회** |
| 습관 발화 | 4회 | 18회 |
| 폴백 비율 | 87.9% | 35.7% |
| 확정 도달 습관 | 0 / 5 | 4 / 5 |
| 종료 시 체력 | A1/B5 (바닥) | A23/B25 |
| 그쳐 | 0~2회 | 11회 |

### 예상 부작용이 실측으로 부정됐다

두 번 예상하고 두 번 틀렸다.

- **"큰기술을 빼면 B 가 소극으로 몰려 지도 3 으로 질 것"** → 세 프로필 전부 지도 3 종료 없음. 견제기가 §6.1 기술진입 −2 를 계속 넣어 막고 있었다
- **"득점 후 그쳐가 잡기를 풀면 H1 발화가 줄 것"** → 오히려 늘었다(3→4). 경기가 길어져 잡기를 다시 세울 기회도 같이 늘었다. 같은 원인이 양쪽으로 작용했다

두 번째는 딸린 효과가 더 있었다 — **H3 이 처음으로 발화했다.** 경기가 길어지자 B 체력이 A 아래로 내려가는 국면이 생겼고, 세 프로필 전부 0회였던 습관이 자연히 풀렸다. 규칙 구멍 하나를 메우니 셋이 같이 풀린 셈이다.

### 규칙 문서가 실측을 들고 있다

`OPPONENT_BRAIN.md` 는 이제 각 규칙 옆에 그 규칙을 만든 수치가 붙어 있다. 문서가 "이렇게 하라"만 적힌 사양서에서 **"이렇게 안 하면 이런 일이 난다"** 가 적힌 문서로 바뀌었다.

## 면접 예상 질문

**"테스트가 145개 초록인데 시스템이 안 돌았다는 게 말이 되나?"**
된다. 단위 테스트는 각 규칙이 **명세대로 동작하는가**를 답하고, 규칙들이 같이 굴렀을 때 **의미 있는 빈도로 발화하는가**는 답하지 않는다. 사다리 각 행은 전부 테스트가 있었고 전부 통과했다. 한 경기에서 1~5행이 0회라는 것은 어느 단위 테스트의 실패도 아니다.

**"그럼 그 스모크는 테스트인가 계측인가?"**
둘 다인데 단언은 최소로 뒀다. `ReadLadderActuallyRuns_NotEveryTurnIsNeutral` 하나만 "0 이면 실패"로 고정하고 나머지는 콘솔로 찍는다. 숫자를 단언하면 튜닝할 때마다 테스트를 고치게 되고, 그러면 테스트가 사양이 아니라 현상 기록이 된다.

**"규칙 문서를 고치는 게 맞나, 코드로 맞추는 게 맞나?"**
이 저장소는 문서가 단일 출처이고 코드와 충돌하면 문서가 이긴다. 그래서 **문서를 먼저 고치고 코드가 따라가는** 순서를 커밋에서도 유지했다 — 개정 5회 전부 `docs:` 커밋과 `feat:` 커밋을 나눴다. 계측 결과로 코드만 고쳤으면 다음 사람이 문서를 읽고 다시 원래대로 되돌린다.

## 말할 가치가 있는 지점

**진단 두 개가 틀렸고, 계측이 고치기 전에 잡았다.**

"2행이 3회 떴는데 유효가 안 났다 — 산술적으로 이상하니 버그일 수 있다"고 보고했다. 지시가 "고치지 말고 판정식 5항을 그대로 찍어서 보고하라"였다. 찍어보니 `[0,3,0,1,0] sum=4 → Yuko` 로 정상 득점하고 있었다. 폐기가 0회라는 데서 거꾸로 추론한 것이었는데 그 추론이 틀렸다.

같은 보고에서 "폐기가 한 번도 안 난다"고도 썼다. 예비 습관 H4b 가 발화하고 있었는데, **예비는 폐기가 나야 점등되므로 그 발화 자체가 폐기의 증거**였다. 계측을 읽는 순서가 틀렸다.

없는 버그를 두 번 고칠 뻔했다. 규칙 시스템에서 "이상해 보인다"는 대부분 관측 부족이지 결함이 아니다.
