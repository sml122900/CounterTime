# 트러블슈팅: 읽기 시스템이 통째로 안 도는데 아무도 몰랐다

2026-08-10 · 상태: **해결. 규칙 개정 3회 + 상시 감시 테스트 1개**

## 문제 상황

상대 브레인 3단계(`LiveReadResolver` + `HabitBrainCommitSource`) 구현이 끝났다.

- 테스트 **145개 전부 초록**
- 대조 모드 지문 **IDENTICAL**
- `CounterTime.Brain` `UnityEngine` 참조 0
- Unity 컴파일 에러 0 · 경고 0

완료 조건을 전부 만족했다. 그런데 헤드리스 스모크를 붙여 수치를 뽑아보니 이랬다.

```
=== A varies (4-cycle) ===
  turns=33  fallback=29 (87.9%)
  habit BigThrowOnGripEdge     fired 1  observed 1
  habit LegTechAfterShido      fired 3  observed 3
  habit TurtleWhenTired        fired 0  observed 0
  ladder row 1: 0   row 2: 0   row 3: 0
  ladder row 4: 0   row 5: 0
  ladder row 6: 33            ← 전부 Neutral
```

**33교환 전부가 6행(Neutral).** 판정식 다섯 항 중 폭이 가장 큰 읽기 항(−3…+3)이 한 번도 0 이 아닌 적이 없었다.

즉 이 세션에 만든 것 — 관측 원장, 지식 등급, 읽기 사다리 6행, 성향 창 — 이 **전부 있는데 아무 일도 안 하고 있었다.** 게임으로 치면 수싸움이 통째로 없는 상태다.

**아무 신호도 없었다.** 예외도, 경고도, 실패하는 테스트도 없었다.

## 시도한 것들

### 1. 먼저 의심한 것 — 리졸버 버그 (아니었다)

사다리 구현을 다시 읽었다. 6행이 위에서 아래로 `return` 만 하는 30줄이고, 각 행에 단위 테스트가 있고 전부 통과한다. `KnownHabitFiredByB_WhenBAttacks_GivesAttackerGotRead` 같은 것들이 **행마다** 초록이었다.

여기서 방향을 틀었다. 사다리가 아니라 **입력**이 문제였다. 사다리는 "B 가 발화한 습관 + A 의 지식"을 요구하는데, 계측을 보면 습관 자체가 50교환에 4번밖에 안 떴다.

### 2. 왜 습관이 안 뜨는가 — 조건을 하나씩 따라갔다

| 습관 | 조건 | 왜 안 서는가 |
|---|---|---|
| H1 | 자기 유효 잡기 ≥ +1 | **B 가 잡기 우위에 못 닿는다** |
| H2 | 지도 받은 뒤 2턴 내 | 지도가 경기당 1회뿐 |
| H3 | 예비 | 폐기가 나야 점등 |

H1 이 근원이었다. B 가 잡기를 다투지 않으니 +1 에 영영 못 닿고, 그러면 진도윤의 간판 습관이 관측 대상이 되지 못한다. 폴백이 88% 인 것과 같은 원인이다 — B 에게 잡으러 갈 이유가 없었다.

### 3. 두 번째 벽 — 확정이 폐기보다 느리다 (산술)

H4(잡기 노림)를 넣자 관측이 쌓이기 시작했다. 그런데 이번엔 다른 게 걸렸다.

- **확정**(수 노트 기록)은 관측 3회 필요. 원장이 교환 해결 *뒤에* 기록하므로 실효 **4번째 발화**부터 읽힌다
- **폐기**는 피해 **2회**면 난다

**A 가 벌줄 수 있는 습관은 읽히기 전에 먼저 사라진다.** 실측에서 H4 가 정확히 관측 3회에서 폐기됐다. 루프가 산술적으로 완주 불가였다.

### 4. 세 번째 벽 — 판정의 절반이 읽을 수 없는 던지기

수치가 이랬다.

```
judgements: None=14 Yuko=7 WazaAri=2   scored by: A=11  B=11
turns=27  fallback=8 (29.6%)
```

27교환에 판정 23건. 폴백에도 큰기술 후보가 있어서, **B 의 던지기 중 상당수가 습관이 아닌 무작위에서 나왔다.** 습관에서 안 나온 던지기는 정의상 읽을 수 없다.

### 5. 진단을 두 번 틀렸다 — 계측이 먼저 잡았다

2행(카논 케이스 3)이 3회 뜨는데 폐기가 0회인 것을 보고 **"2행이 득점을 못 하고 있다, 버그일 수 있다"** 고 보고했다. 지시가 "고치지 말고 판정식 5항을 그대로 찍어라"였다.

```
ex13: terms[grip,read,stam,tech,posture]=[0,3,0,1,0] sum=4 -> Yuko by A
ex14: terms[grip,read,stam,tech,posture]=[0,3,2,1,0] sum=6 -> WazaAri by A
```

정상 득점하고 있었다. 폐기 0회에서 거꾸로 추론한 것이 틀렸다.

같은 보고에서 **"폐기가 한 번도 안 난다"** 고도 썼는데, 그것도 틀렸다. 예비 습관 H4b 가 발화하고 있었고 — **예비는 폐기가 나야 점등되므로 그 발화 자체가 폐기의 증거**였다. 계측을 손에 들고도 읽는 순서가 틀렸다.

없는 버그를 두 번 고칠 뻔했다.

## 최종 해결법

원인이 셋이었고 전부 **숫자가 아니라 규칙** 이었다.

### (1) 습관 H4 `잡기 노림` 신설 — `OPPONENT_BRAIN §4.1`

조건 `자기 유효 잡기 < +1`, 행동 `오른소매 노림`(기술 없음). 폐기되면 **삭제가 아니라 교체** — 예비 H4b 가 왼소매를 노린다. 잡기를 아예 안 가면 B 가 자멸하기 때문이다.

기술이 없으므로 **비공격 습관**이고, 그래서 사다리 2행(A 공격 + B 비공격 습관 + 확정 → 완전간파)의 대상이 된다. `MATCH_RULES §4.1` 카논 케이스 3 이 이 습관 없이는 플레이에서 도달 불가였다.

폴백 가중치도 같은 문턱(+1)으로 잡기를 지향하게 했다 — H4 가 25% 빗나간 턴을 폴백이 메워야 하기 때문이다.

### (2) 피해는 확정 뒤부터 센다 — `OPPONENT_BRAIN §4.2`

```csharp
public void RegisterDamage(HabitId id, ObservationLedger ledger)
{
    if (!ledger.IsConfirmed(id)) return;   // ← 선행조건
    ...
}
```

`bool` 이 아니라 **원장을 받게** 했다. 확정 검사가 안에 있으니 부르는 쪽에 틀릴 자리가 없다.

서사도 이쪽이 맞다 — B 가 습관을 버리는 건 *간파당했음을 인지*해서인데, 확정 전에는 A 가 읽은 게 없고 B 도 알 방법이 없다. 운 좋은 두 방은 tell 이 아니다.

### (3) 폴백은 큰기술을 내지 않는다 — `OPPONENT_BRAIN §4`

폴백의 공격 후보를 견제기 하나로 줄였다. 견제기는 판정을 발화하지 않으면서 §6.1 기술진입 −2 는 받으므로, B 가 소극으로 몰리지 않으면서 점수도 양산하지 않는다.

목적은 이 성질이다 — **B 의 모든 큰기술이 습관에서 나온다 = 원리적으로 전부 읽을 수 있다.**

### (4) 그리고 상시 감시 테스트

같은 실패가 조용히 돌아오지 못하게, 스모크에 단언을 하나 남겼다.

```csharp
[Test]
public void ReadLadderActuallyRuns_NotEveryTurnIsNeutral()
{
    // 한 경기가 전부 6행이면 읽기 시스템이 한 번도 안 도는 것이다
    Assert.Greater(nonNeutral, 0);
}
```

숫자를 단언하지 않는다 — 0 이냐 아니냐만 본다. 튜닝은 사람이 정한다.

### 결과

| | 전 | 후 |
|---|---|---|
| 사다리 1~5행 | **0회** | **11회** |
| 습관 발화 | 4회 | 18회 |
| 폴백 비율 | 87.9% | 35.7% |
| 확정 도달 습관 | 0 / 5 | 4 / 5 |

덤으로 두 번째 규칙 구멍이 드러났다 — 체력이 30교환에 바닥나는데 §2 는 60~80교환을 상정한다. 회복이 그쳐에 묶였는데 그쳐가 경기당 0~2회였다. `MATCH_RULES` v3.4 §4.3(득점 후 그쳐)로 메웠고, 그 결과 H3 까지 처음으로 발화했다.

## 이력서 소재 한 줄

테스트 145개가 초록이고 대조 모드 회귀도 0인 상태에서, 헤드리스 계측으로 **읽기 시스템이 한 경기 33교환 내내 한 번도 발화하지 않는다**는 것을 발견해 규칙 3건을 개정하고 재발 감시 테스트를 남겼다.

## 다음에 같은 일을 겪는다면

**단위 테스트는 규칙이 명세대로 도는가를 답하고, 규칙들이 같이 굴렀을 때 의미 있는 빈도로 발화하는가는 답하지 않는다.** 확률·상태·우선순위가 얽힌 시스템은 통합 계측 없이 "완료"라고 말할 수 없다.

그리고 계측을 손에 들고도 읽는 순서를 틀릴 수 있다. **이상해 보이면 고치기 전에 원값을 찍어라** — 규칙 시스템에서 "이상하다"는 대부분 관측 부족이지 결함이 아니다.
