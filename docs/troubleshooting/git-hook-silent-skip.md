# 스탬프 훅이 두 번 조용히 건너뛴 문제

작성 2026-08-09 · **상태: 해결**

문제 두 개다. 원인은 다르지만 증상이 똑같다 — **에러 없이 exit 0, 그런데 아무것도 안 함.**

검증 장치가 침묵으로 실패하면 없는 것보다 나쁘다. 있다고 믿게 되기 때문이다.

---

## 문제 1 — 하드코딩한 경로 목록이 문서 이동을 못 따라갔다

### 문제 상황

`pre-commit` 훅이 문서 스탬프를 자동 갱신하도록 되어 있었다. 원안은 이랬다.

```sh
DOCS="MATCH_RULES.md CORE_DESIGN_MatchEngine.md"

staged=$(git diff --cached --name-only --diff-filter=ACM)
for f in $DOCS; do
  printf '%s\n' "$staged" | grep -qx "$f" || continue
  ...
done
```

그런데 이 저장소에서 문서는 `md/` 아래에 있다.

```
$ git diff --cached --name-only --diff-filter=ACM
md/MATCH_RULES.md          ← git 이 돌려주는 것
```

`grep -qx "MATCH_RULES.md"` 는 **완전 일치**를 요구한다. `md/MATCH_RULES.md` 는 절대 안 맞는다. `|| continue` 로 넘어가고 루프가 끝나고 **훅은 정상 종료한다.**

커밋은 성공한다. 스탬프만 낡은 채로 들어간다.

### 왜 생겼나

패치 문서에 `# Adjust paths if the docs move` 주석이 있었고, 실제로 문서가 `md/` 로 옮겨진 뒤였다. 경로를 고치는 것 자체는 지시대로였다.

진짜 원인은 **훅이 대상을 목록으로 알고 있었다**는 구조다. 목록과 현실이 갈라질 수 있고, 갈라졌을 때 알려주는 장치가 없다.

경로만 `md/` 로 고치면 이번은 넘어가지만 **다음에 문서를 옮기거나 세 번째 문서에 스탬프를 붙이면 같은 자리에서 또 물린다.**

### 최종 해결법

목록을 없애고 파일이 스스로 신고하게 했다. **1행이 스탬프 형식이면 관리 대상, 아니면 무시.**

```sh
git -c core.quotePath=false diff --cached --name-only --diff-filter=ACM -- '*.md' \
  | while IFS= read -r f; do
  [ -f "$f" ] || continue
  head -n 1 "$f" | tr -d '\r' \
    | grep -qE '^<!-- v[^ ]+ \| body:[0-9a-f]{7} -->$' || continue
  sh tools/stamp.sh "$f"
  git add "$f"
done
```

플레이스홀더 스탬프를 붙이는 것이 곧 등록이고, 1행을 지우면 해제된다. 문서를 옮겨도 안 깨진다.

### 검증

먼저 전제부터 확인했다. **git pathspec 의 `*` 는 `/` 를 넘는다** (셸 glob 과 다르다). 이게 안 되면 `-- '*.md'` 가 `md/` 안을 못 봐서 훅 전체가 무성하게 실패한다.

```
$ git diff --name-only HEAD~1 HEAD -- '*.md'
md/STATUS.md          ← 하위 디렉터리를 넘어서 매칭됨
```

그다음 세 가지를 실제로 스테이징해 훅을 돌렸다.

| 스테이징한 것 | 기대 | 결과 |
|---|---|---|
| `PROBE_stamped.md` (**저장소 루트**, 어떤 목록에도 없던 위치) | 자기등록 | `stamp: PROBE_stamped.md -> 784d082` |
| `md/MATCH_RULES.md` | 갱신 | `stamp: … -> 090836e` |
| `md/STATUS.md` (스탬프 없음) | 무시 | 출력 없음 |
| `md/UNSTAMPED_probe.md` (스탬프 없음) | 무시 | 출력 없음 |

**정리를 반드시 해야 한다.** 자기등록 방식에서는 스탬프가 붙은 테스트 파일을 남기면 이후 모든 커밋에서 훅이 계속 손대는 유령 문서가 된다. 구 방식(하드코딩 목록)은 무시했을 것이다. 등록이 자동인 만큼 **뒷정리도 절차에 포함된다.**

프로브 제거 후 확인: 디스크에 없음, 추적 안 됨, `git log --all` 에 없음, 스탬프 달린 추적 문서는 정확히 2개.

## 문제 2 — git 이 비ASCII 경로를 이스케이프해서 돌려준다

### 문제 상황

문서 1이 고쳐진 뒤에도 같은 종류의 구멍이 남아 있었다. 한글 파일명이다.

```
$ git diff --cached --name-only --diff-filter=ACM -- '*.md'
"md/\352\270\260\354\210\240\353\252\205\354\204\270.md"
```

git 은 `core.quotePath` 가 기본 `true` 라서 비ASCII 경로를 **따옴표로 감싸고 8진 이스케이프**한다. 이 문자열은 실제 파일 경로가 아니다.

```sh
[ -f "$f" ] || continue     # ← 여기서 걸러진다
```

스탬프가 붙은 정상 문서인데 **조용히 건너뛴다.** 문제 1과 완전히 같은 증상이다.

### 재현

추측으로 두지 않고 실제로 만들어 확인했다.

```
$ printf '<!-- v1.0 | body:0000000 -->\n기술명세 본문\n' > md/기술명세.md
$ git add md/기술명세.md
$ sh tools/githooks/pre-commit
hook exit=0        ← 스탬프 안 찍힘
```

### 최종 해결법

```sh
git -c core.quotePath=false diff --cached --name-only …
```

`-c` 는 **이번 호출에만** 적용되므로 저장소 설정을 건드리지 않는다. POSIX sh 그대로다.

```
$ sh tools/githooks/pre-commit
stamp: md/기술명세.md -> d33a053
```

### 왜 `-z` 를 안 썼나

`--name-only -z` 로 NUL 구분하는 게 정석처럼 보이지만, 읽는 쪽이 `read -d ''` 를 써야 한다. **`read -d` 는 bash 확장이다.**

셔뱅이 `#!/bin/sh` 인데 Git Bash 에서만 우연히 돌고, `/bin/sh` 가 dash 인 환경에 가면 조용히 깨진다. **지금 고치려는 실패와 정확히 같은 종류로 바뀐다.** 이득이 없다.

남는 구멍은 파일명에 개행이 든 경우뿐이고 그건 병적인 케이스다.

### "오늘은 영향 없음"으로 미루지 않은 이유

이 저장소에 한글 문서 파일명은 현재 없다. 그래도 고쳤다.

- 한글 파일명이 들어올 통로가 이미 여럿이다 — 시나리오 보드 JSON, 모캡 클립 목록, 기술명 기반 문서
- 이 세션에서 쫓아낸 결함이 전부 **"지금은 괜찮은데 조용히 빠지는"** 부류였다
- 고치는 비용이 토큰 하나다

발현 시점만 미래일 뿐 같은 종류다.

## 재발 방지

- **검증 도구는 "대상을 못 찾음"과 "대상이 정상"을 구분해야 한다.** 둘 다 exit 0 이면 도구가 죽은 걸 알 방법이 없다
- 훅·린터·체커에 **경로 목록을 하드코딩하지 않는다.** 파일 스스로 소속을 신고하게 하면 이동에 안 깨진다
- `git ... --name-only` 를 스크립트에서 쓸 때는 `-c core.quotePath=false` 를 붙인다. 한글 경로가 있는 저장소에서는 기본값이 함정이다
- 셸 스크립트에 확장 문법을 넣을 때 **셔뱅과 맞는지** 본다. `#!/bin/sh` 에 bash 확장을 쓰면 환경에 따라 조용히 깨진다
- 자기등록 방식의 검증 도구는 **테스트 픽스처 정리가 절차의 일부다.** 남으면 도구가 그걸 진짜 대상으로 채택한다

## 부가 — 점검 명령이 정상 상태에서 실패하면 안 된다

`CLAUDE.md` 에 세션 시작 점검으로 `sh tools/stamp.sh --check md/*.md` 를 넣으려다 잡았다. glob 이 `md/STATUS.md`(스탬프 없음)를 끌고 오는데 `--check` 가 exit 2 로 죽었다.

**아무 문제 없을 때 에러를 내는 점검은 사람이 무시하는 법을 배운다.** 명령을 좁히는 대신(그러면 하드코딩 목록이 돌아온다) `--check` 에서 미등록 파일을 건너뛰게 고쳤다 — 훅과 같은 규칙이다. 명시적으로 이름을 준 경우의 rewrite 모드는 여전히 exit 2 로 남겼다. 그건 진짜 실수니까.

## 이력서 한 줄

> 문서 무결성 검증 훅이 경로 목록 하드코딩과 git 의 비ASCII 경로 이스케이프로 두 차례 무음 실패(정상 종료 후 미실행)한 것을 재현·수정하고, 대상 판별을 경로가 아니라 파일 내용으로 옮겨 문서 이동에 견디게 했습니다. 정석으로 보이는 `-z` 대신 `core.quotePath=false` 를 택한 근거는 `read -d` 가 bash 확장이라 `#!/bin/sh` 환경에서 같은 종류의 무음 실패로 바뀌기 때문입니다.
