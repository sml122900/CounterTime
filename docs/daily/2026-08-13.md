## 한 일

### 1. §H 3.5b-뼈대 — 지도·연습 대회 대진표·경기 흐름

`Assets/_Project/Scripts/Game/Meta/`를 신설했다. `TournamentBracket.cs`(순수
로직 — 32강 그리드 생성, 필러 30명 코인플립 진출, 라운드 전환·메달 판정 규칙)와
`MetaFlowController.cs`(런타임 캔버스 UI + 오케스트레이션, `LiveMatchPanel`과
같은 "씬 무수정, 코드로 짓는다" 패턴).

기존 `LiveMatch` GameObject(엔진+3D 무대+UI)를 매 라운드 다시 짓지 않고 재사용하기로
했다 — `LiveMatchRunner.Rebuild(seed)`와 `LiveMatchPanel.ResetForNewMatch()`를
최소로 추가해, 비활성화만 했다 다시 켜는 방식으로 3D 무대 재구성 비용을 없앴다.
이 과정에서 **Awake 타이밍 경쟁**을 하나 발견해 순서로 해결했다 — 상세는
`docs/decisions/livematch-gameobject-reuse-awake-timing.md`.

`SaveData.cs`에 `TournamentRound` enum과 `CareerSaveData.practiceCupRound`
필드를 추가(META_DESIGN 원 스키마엔 없던 필드 — 진행 중 라운드가 저장 안 되면
재접속 시 대회 진행 상태를 잃어버려서). `PlayModeSetupMenu.cs`의 진입점을
지도로 바꾸고, LiveMatch는 에디터에서 미리 비활성으로 지어 "경기 시작" 클릭
시에만 켜지게 했다.

Play 실측(RunCommand로 실제 엔진 매치를 자동 진행): 패배 경로(32강 패배→
`Lost`)와 승리 경로(32강→16강→8강→4강 패배→동메달전 자동 전환→동메달전
승리→`Bronze`)를 각각 실제 매치 5~6판으로 완주해 확인. 이 과정에서
`GameObject.Find`가 비활성 오브젝트를 못 찾는다는 걸 다시 겪었다 —
상세는 아래 트러블슈팅 항목.

### 2. §H 3.5b-로스터 — 구별되는 상대 6명 실저작 (습관만)

ROSTER.md 근거로 진도윤 임시 배치를 6명으로 교체. 콤보([step7])·예측
되치기([step5])·적응([step6])·평판 확산은 전부 이월 — 이번엔 습관만으로
싸운다.

**습관 저작 전 구조 파악**: 기존 `HabitCatalogue`의 5개 습관이 전부 진도윤
전용으로 기술명이 하드코딩돼 있었다("업어치기" 등). 새 상대마다 새
`HabitId` 값 + `HabitCatalogue.Build` case가 필요하다고 판단해 9개를
추가했다(`HabitId` 5→14). 대부분 기존 `IHabitContext`(그립·체력·지도
타이밍)로 표현됐지만 둘은 안 됐다 — `OpponentSetupActive`(서도현 H1,
"예고"를 §4.4 흔들기의 실제 게임 상태로 재해석)와 `OwnBalance`(서도현
H2 + 임준철 변칙기). 둘 다 인터페이스 문서 자체의 "새 습관이 실제로
요구할 때만" 규약대로 추가하고, 관문 테스트를 갱신해 그 사실을 diff에
남겼다.

**변칙기 하드 규칙, 실제로는 존재하지 않았다**: 작업 지시가 "말아업어치기와
같은 방식"이라고 전제했는데, 실측 결과 그 방식 자체가 어디에도 구현돼
있지 않았다(테스트 주석·설계 문서에만 존재). 임준철의 안오금띄기를
발화시키려면 진도윤 것도 같이 만들어야 했다 — `SurpriseTechnique.cs`
신규, `HabitState.TryFireSurprise`(경기당 1회), `HabitBrainCommitSource`가
사다리를 그대로 돌린 뒤(턴 계수 보존) 발화 시 결과를 덮어쓰는 구조.
상세는 `docs/decisions/surprise-technique-hard-rule.md`.

**"두 갈래를 번갈아"**: 임준철(어깨매치기/발뒤축걸기)과 오재훈(허리후리기/
밭다리걸기) 둘 다 ROSTER가 이걸 요구했다. 진짜 매 순간 50/50 무작위는
`HabitAction`/`HabitLadder`(공유 Brain 인프라) 확장이 필요해 범위 밖으로
판단하고, 같은 조건에 쿨다운 2를 나란히 준 두 습관으로 근사했다 — 상세는
`docs/decisions/habit-alternation-via-cooldown.md`.

**결승 진도윤 상향**(ROSTER §R5): 습관 신뢰도 0.75→0.65(전 습관), scoutingLevel
0→1 시드(효과는 여전히 inert). 영향받은 테스트 3개를 실제 값을 따라
갱신했다 — 결론(1.0이 아니다/여전히 inert하다)은 안 바뀜, 숫자만.

**대진표 배선**: `LiveMatchRunner`에 `_opponentFactory` 필드 +
`SetOpponent(Func<...>)` 최소 추가. `MetaFlowController.OpponentFactoryFor(round)`가
라운드→Brain 팩토리 매핑을 담당하고, `TournamentBracket`은 이름/세이브id
매핑만 갖는다 — Brain 어셈블리 참조를 그쪽에 안 늘리려는 판단.

**문서 동기화**: 작업 지시의 8강/4강 이름(서도현/임준철)이 ROSTER.md 초안의
placeholder(서강윤/임세라)와 달라서, ROSTER.md도 같이 갱신(v1.0→v1.1).

**검증**: Unity MCP 컴파일 0/0. 하니스 253→257(신규 단위테스트 4개 — 변칙기
경기당 1회 / 사다리 덮어쓰기+관측 안 됨 / 임준철 A-B-A-B 교대 / 서도현
좁은→넓은 순서). Play 스모크로 6상대 전부 이름 일치 + 공격 빈도가 확연히
다름(황도철 최다·문준배/서도현 0·진도윤 최다) 확인, 변칙기 두 종을 실제
문턱(체력<30, 밸런스<50) 너머까지 몰아붙여도 에러 없이 정상 종료함을 확인.
