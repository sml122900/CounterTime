## 한 일

### 1. 방사형 메뉴 구현 (`64ddaf3`)

`BuildAxisControl`을 트리거(축 이름만 표시하는 74×36 컴팩트 버튼) + 요약
텍스트(트리거 아래 별도) + 휠 컨테이너 구조로 재작성했다. 트리거 자체에
"손: 오른소매"급 긴 라벨을 달면 그 절반 폭이 승인된 반지름 여유를 깎아먹는다는
걸 구현 중 깨닫고 설계를 바꿨다 — 트리거는 축 이름만, 현재 선택은 별도
텍스트로 뺐다.

`RebuildAxisOptions`는 극좌표(반지름 R, -90°~+90° 균등 분배)로 옵션 버튼을
배치한다. 손(R=130)·코어(R=90)·하체(R=100) — 항목이 최대 10개인 손이 가장
완만한 곡률을 갖도록 반지름을 키웠다.

`ToggleDropdown`/`OpenWheel`/`CloseAllWheels`로 한 번에 휠 하나만 열리게
하고, 열려 있는 동안 나머지 두 축의 트리거+요약은 숨긴다 — 세로 110px
간격으로 쌓인 트리거끼리 반지름 130 휠이 열리면 옆 트리거 자리까지 닿기
때문이다. 확정 게이트(`_handChosen`/`_coreChosen`/`_legsChosen`)와 제출·
리셋 배선은 기존 그대로 재사용했다.

### 2. 검증 중 발견한 자체 겹침 수정 (`64ddaf3`)

Play 모드 재검증 중 요약 텍스트(Y 오프셋 -22)가 트리거 하단(-18)과 6px
겹치는 걸 실측으로 잡았다. 요약 텍스트 자신의 높이(20px, 중심 기준 ±10)까지
감안해 -32로 내려 4px 여유를 뒀다.

### 3. 승인 근거 재검증 → 실측이 뒤집음 (`64ddaf3`)

사전 조사 단계에서 "R=130이면 A와 24px 여유"라고 계산해 승인받았던 값을,
구현 완료 후 카메라 투영(`Camera.WorldToViewportPoint` → `ArenaBackground`
RawImage 스크린 좌표 변환)으로 A·B의 실제 화면 바운딩 박스를 정밀 실측해
재검증했다. 결과: A는 x=47~806(화면 폭의 42%)로 트리거 위치(x=25)에 거의
붙어 있었고, 손·코어·하체 세 축 옵션 버튼 15개 전부가 A와 겹쳤다(최소 15px,
최대 145px). 부채꼴의 ±90° 지점이 반지름과 무관하게 항상 트리거 x좌표
근처에 고정된다는 성질(`cos(90°)=0`) 때문에 반지름을 아무리 조정해도 구조적
으로 피할 수 없다는 것도 함께 확인했다.

→ `docs/troubleshooting/radial-menu-clearance-miscalculation.md`

### 4. 처리 방안 재확인 → 딤 처리 반영 (`64ddaf3`)

승인된 설계를 다시 흔들지 않고 실측치·기하학적 불가능성을 그대로 보고,
AskUserQuestion으로 처리 방안을 물었다. "겹침 허용 + 휠이 열린 동안 배경
딤 처리"를 선택받아, `ArenaBackground.color`를 휠 열림 시 45% 밝기로 낮추고
닫히면 100%로 복원하는 두 줄만 추가했다. 반지름·각도·트리거 위치는 무수정.

### 5. 전체 재검증 + STATUS 갱신 (`64ddaf3`, `a60e84e`)

Unity MCP 컴파일 0/0. Play 모드 실클릭으로 3축 각각 열기(딤 확인)/선택
(휠 자동 닫힘+딤 해제)/닫기, 확정 게이트 0/3→3/3 전환(Idle→ShidoYellow),
제출 후 리셋을 전부 확인했다. 7개 해상도(1920~320) 닫힌 상태 전부
zeroSize=0/overlaps=0/wrapped=0 — 1024×768에서 뜬 "IPPON 스트립 x
RowA/RowB" 겹침 경고는 고정밀 재측정으로 -0.00003px(부동소수점 경계 접촉)
임을 확인해 오탐 처리했다(스코어보드는 이번 범위 밖, 무수정). 하니스
209/209, 지문 IDENTICAL. STATUS.md에 Next Up 최상단 갱신 + Session Log
