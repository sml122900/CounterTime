# 2026-08-19 작업 일지 — 뜯긴 존 재잡기 쿨다운(§2b v4.3 후속)

## 한 줄 요약

직전 세션(잡기 개편 2차, 뜯기 v4.3)에서 열어둔 후속 3건을 처리했다 — ①
"오른소매 비견고 + 팔꿈치로 뜯기 3연속" 시나리오 이벤트 로그 재현, ② 뜯긴
존 재잡기 쿨다운(사용자 확정 규칙) 신규 구현, ③ 해제 이벤트 "확보" 오표기가
이미 해결돼 있는지 코드 재확인. ②가 이번 세션의 실제 작업량 대부분이었고
①·③은 코드 추적·재현으로 답한 확인 항목이었다.

## 한 일

### 1. 재현 검증 — "오른소매 비견고 + 팔꿈치로 뜯기 3연속"

`GripSystem.ReleaseHold`가 실제로 호출되는지, 같은 교환 내 재확보가
가능했는지를 임시 스크래치 테스트(`ZZZScratchReproTest`, 검증 후 삭제)로
이벤트 로그를 직접 찍어 확인했다. 쿨다운 구현 전 기준으로는 뜯기 직후
같은 교환에 상대가 재확보를 시도하면 그대로 성립했을 구조였다는 것을
로그로 확인 — 이게 ②의 근거가 됐다.

### 2. 뜯긴 존 재잡기 쿨다운 — 신규 구현

사용자 확정 규칙("뜯기 성공으로 해제된 존은 그 교환 + 다음 1교환 동안
재잡기 불가, 매트릭스보다 우선")을 `MatchEngine`에 구현했다.

- `_tearRegripCooldown` — (victim, DefenseZone) 키의 존별 카운터 배열 신설.
  뜯기 성공 시 `1 + TearRegripCooldown`(⚙, 기본 1)으로 세팅.
- `ResolveGripExchangeRevised`의 `aSucceeds`/`bSucceeds` 계산 맨 앞에
  `IsRegripBlocked` 체크를 추가 — 방어 존·가슴깃 노림·같은 쌍 맞잡기 등
  기존 매트릭스 전체보다 먼저 걸린다.
  카운터는 매 교환 끝에 1씩 감소(`TickTearRegripCooldowns`, 바닥 0).
  그쳐(matte) 두 지점(`CallMatte`/굳히기 탈출) 모두에서 배열을 리셋해
  `Grip.OnMatte()`와 생명주기를 맞췄다.
- 카운터 초기값을 쿨다운 값 그대로 안 쓰고 `1 +`를 더한 이유, 시퀀스
  검산 과정: `docs/decisions/grip-tear-regrip-cooldown.md`.
- `MATCH_RULES.md` §2b 뜯기 절에 소결정 (c)로 규칙 원문 반영(문서가
  코드 상위 — CLAUDE.md 컨벤션).
- 커버 테스트 2개(`GripTearRegripCooldownTests`) 신설 — "그 교환 실패 →
  다음 교환도 실패 → 그다음 교환부터 성공" 시퀀스, "무관한 존은 안
  막힌다" 각각 고정.
- 스크래치 테스트로 최종 재검증: "오른소매 비견고 + 팔꿈치로 뜯기
  3연속" 시나리오가 실제로 "뜯기 성공(교환1) → 재확보 실패(교환1,2) →
  재확보 성공(교환3)"으로 로그에 그대로 나오는 것 확인 후 스크래치
  파일 삭제.

**검증**: 하니스 326 → 327/327(누적), 42노드 지문 IDENTICAL.

### 3. 내레이션 "확보" 오표기 — 코드 재확인, 추가 수정 불필요

해제 전용 `GripChanged(Part=None)` 이벤트가 `LiveMatchPanel.EventSummary`에서
"— 확보"로 잘못 뜨는 문제가 있었는지 확인 요청을 받았다. STATUS.md 기록을
그대로 믿는 대신 코드를 직접 추적한 결과, §2a(구식)·§2b v4.3 두 경로 모두
해제 이벤트보다 더 구체적인 이벤트(`TearResolved`/`GripTearAttempted`)가
이벤트 리스트에 **먼저** 들어가도록 이미 순서가 조정돼 있었다(§2b 쪽은
`MatchEngine.cs`의 명시적 주석까지 남아 있음). `BuildOutcome`이 "첫 번째
뜻 있는 이벤트"만 뽑으므로 "확보" 문구는 애초에 노출될 경로가 없다 — 직전
세션에서 이미 해결된 것을 재확인만 했다.

## 기술 결정

- `docs/decisions/grip-tear-regrip-cooldown.md` — 자연어 규칙("그 교환 +
  다음 1교환")을 정확한 길이로 차단하는 카운터를, 초기값에 `1 +`을 더하고
  "매트릭스 검사 → 감소" 순서를 고정하는 방식으로 모델링한 판단. 오프바이원
  위험을 코드로 겪기 전에 시퀀스를 손으로 검산해 잡았다는 게 핵심.
