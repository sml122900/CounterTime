### 3. 문서 스탬프 — 두 번의 무음 실패

의뢰는 "문서에 `<!-- v3.1 | 33ecd10 -->` 헤더를 넣고 편집과 같은 커밋에서 갱신하라"였다.

**1차 문제 — 자기참조.** 커밋 해시를 파일에 쓰면 내용이 바뀌고 해시도 바뀐다. 수렴하지 않는다. 게다가 커밋 안 한 편집을 못 잡는다 — 스탬프의 존재 이유였던 실패를 정확히 못 잡는 것이다. → **본문 해시**로 교체(`773672f`). 1행을 뺀 본문의 `git hash-object`. 스탬프를 쓰는 행위가 스탬프가 재는 대상을 안 바꾸므로 한 번에 수렴한다.

**2차 문제 — 훅의 하드코딩 경로.** 훅은 `DOCS="MATCH_RULES.md ..."` 였는데 문서는 `md/` 아래에 있다. `git diff --cached` 는 `md/MATCH_RULES.md` 를 돌려주고 `grep -qx "MATCH_RULES.md"` 는 절대 안 맞는다. **에러 없이 exit 0.** 경로만 고치면 다음에 옮길 때 또 물린다 → 1행이 스탬프 형식인 staged `*.md` 를 스스로 찾는 방식으로 교체(`b1afcbe`).

**3차 문제 — 비ASCII 경로.** git 은 `--name-only` 에서 비ASCII 경로를 이스케이프한다. 한글 파일명이 `"md/\352\270\260..."` 로 와서 `[ -f ]` 를 통과 못 하고 **또 조용히 건너뛴다.** `md/기술명세.md` 로 재현한 뒤 `-c core.quotePath=false` 로 고쳤다(`842cfe3`).

셋 다 같은 종류다 — **틀린 답을 내는 게 아니라 아무것도 안 하고 성공했다고 보고하는** 실패.
