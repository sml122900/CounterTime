# 2026-08-14 (밤, 9차) 작업 일지 — 손 스테이지1 트리거 겹침 근본 수정

> 같은 날 앞선 세션(`docs/daily/2026-08-14-grip-revision.md`, 3~8차 —
> 잡기 개편 1차 + 휠 라벨을 실측 기반 극좌표 배치로 전면 교체) 직후 이어진
> 별도 세션. 8차가 "겹침 0·화면 이탈 0"을 달성했다고 보고했지만, 검사
> 대상에 축 트리거 라벨 자체가 빠져 있었다는 걸 사용자가 신고해 다시 잡았다.

## 한 줄 요약

손 스테이지1(오른손/왼손/회피 3항목)의 "왼손" 옵션이 "손" 트리거 라벨을
가리고 있었다. 단순히 배치 알고리즘을 개선하는 것으로는 못 푸는 문제였다 —
트리거가 화면 왼쪽 끝에서 45px밖에 없어서, 항목이 트리거 방향에 있으면
반지름을 얼마로 잡든 세이프 마진이 허용하는 반지름이 트리거 자신의 반폭보다
작아진다는 걸 계산으로 증명했다. 안전 게이트에 트리거 키프아웃존 + 항목 간
쌍별 AABB 검사를 추가하고, 실패 시 쓰는 마지막 방어선을 원형 클램프(항목끼리
겹칠 수 있던 버그)에서 트리거 위/아래 세로 스택으로 교체했다.

## 한 일

### 1. 진단 — "더 넓게 펼치기"만으로는 원천적으로 안 풀린다는 걸 증명

1차 시도(남는 여유를 아크 전체에 고르게 분배)를 넣고 재실측하니 화면 이탈은
0이 됐지만 정중앙에 놓인 항목("왼손")이 트리거와 정확히 겹쳤다. 원인을
계산으로 추적했다: 트리거(`TriggerX=55`)는 화면 왼쪽 끝(세이프 마진 10px
제외)에서 45px밖에 없다. 항목이 트리거 방향(θ=180)에 가까울수록 세이프
마진이 허용하는 반지름이 좁아지는데, 반지름을 키워도 x 오프셋은 점근적으로
항목 폭의 절반(약 -28px)에 수렴할 뿐 세이프 마진 문턱(-17px)을 절대 못
넘는다 — 즉 어떤 배치 알고리즘을 쓰든 이 방향에 놓이는 항목은 트리거와
겹칠 수밖에 없다는 걸 수식으로 확인했다.

### 2. 수정 — 안전 게이트에 트리거 키프아웃존 추가

`AllWithinSafeArea`(배치 결과가 화면 세이프 영역 안에 있는지 검사하는
함수)에 트리거 자신의 74×36 박스(원점 중심)와의 AABB 비겹침 검사를 추가했다.
겹치면 그 반지름/폭 조합은 실패 처리되어 바깥 재시도 루프(반지름 확대·폭
축소)가 다른 조합을 찾는다 — 화면 경계 검사와 완전히 같은 계약.

### 3. 수정 — 마지막 방어선을 원형 클램프에서 세로 스택으로 교체

메인 루프가 못 찾으면(손 스테이지1처럼 물리적으로 불가능한 경우가 실제로
있다는 걸 이번에 처음 확인 — "실측상 도달하지 않는다"던 8차의 가정이
틀렸다) 쓰는 "마지막 방어선"이 문제였다. 옛 방어선은 이상적인 각도 위치를
구한 뒤 항목마다 독립적으로 화면 안쪽으로 클램프했는데, 여러 항목이 같은
클램프 목표로 동시에 밀리면 서로 겹쳤다(실측으로 실제 확인). `FallbackStackedLayout`
(신규)이 항목을 입력 순서 앞/뒤 절반으로 나눠 트리거 위/아래 두 세로 밴드에
균등 간격으로 쌓는다 — 밴드 자체가 Y축만으로 트리거와 분리되므로 절대 안
겹치고, 같은 밴드 안 항목끼리도 균등 간격이 겹침을 막는다.

### 4. 재검증 중 추가 발견 — 각도 간격만으론 인접 항목 AABB 겹침도 못 막는다

전 축을 재검증하던 중 하체(4항목: 공격/중립/수비/카운터 준비)에서 "공격"과
"중립"이 5px 겹치는 걸 실측으로 발견했다. 각도 간격(`PolarGapDeg`)은
원둘레를 따라 잰 호 길이 여유일 뿐, 접선 방향이 화면 축과 안 맞으면
유클리드 거리가 그보다 작을 수 있다는 걸 처음 재확인한 것 — 손 스테이지1
때와 달리 이번엔 트리거가 아니라 항목끼리였다. 안전 게이트에 전 항목 쌍별
AABB 검사를 추가해 해결(재시도 루프가 반지름을 키워 자동 해소).

상세 기술 진단·재발 방지: `docs/troubleshooting/hand-wheel-trigger-keepout.md`.

## 세션 중 겪은 것(환경 문제, 제품 결함 아님)

Unity MCP가 다른 프로젝트(`My-Favorite-Random-Game`)로 여러 차례 연결이
넘어갔다 — 두 Unity 에디터가 동시에 열려 있어 MCP가 포커스 기준으로 연결
대상을 바꾼 것으로 추정. 원인은 `PlayModeSetupMenu.Setup()`의 씬 저장 확인
다이얼로그(`EditorSceneManager.SaveCurrentModifiedScenesIfUserWantsTo`)가
CounterTime 에디터를 블로킹하고 있었던 것 — 사용자가 씬을 저장해 다이얼로그를
해소하자 정상화됐다. 그 임시 씬(`Assets/Scenes/PlayModeSetup_temp.unity`)은
빌드 설정에 등록돼 있지 않고 다른 어디서도 참조되지 않아 세션 종료 시 삭제.
