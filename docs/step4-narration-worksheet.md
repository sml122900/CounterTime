# 4b — 결과 노드 서술 대조표 (사람이 채울 것)

작성일 2026-08-10 야간. `docs/step4-result-node-dump.md` (4단계 (a) 덤프)의 실측을 전제로 한다.

이 표는 `CounterTime.Game.Match.ResultNarrationTable` 의 초기 데이터를 채우기 위한
작업지다. **좌측 원문은 절대 고치지 말 것.** 우측 빈칸(Judgement / TechniqueId /
IsCounter)에 값을 채우고, 그 값으로 `ResultNarrationTable.Add(judgement, techniqueId,
isCounter, "서술 문구")` 를 호출하는 코드를 사람이 직접 추가한다 — 이 문서 자체는
데이터가 아니라 배정 작업지다.

`TechniqueSpec` 에는 표시명 필드가 없다(4단계 (a) 덤프 §2.1 확인 사실) — 아래 좌측
문구를 그대로 서술 문구로 써도 되고, 다듬어도 된다. 단 **좌측 "원문" 칸 자체는 원문
그대로 유지**한다.

## 1. 9개 판정식 노드 + 서술이 갈라진 이웃 노드 원문

## 2. 코드에서 긁은 TechniqueId 전수 (play mode 에서 실제 발생 가능한 것)

### 2.1 브레인 경로 (습관 AI, `CounterTime.Brain`) — 실명

| TechniqueId | Cost | Class | 출처 |
|---|---|---|---|
| `업어치기` | BigThrow | Standard | `HabitCatalogue.cs:31` (H1) |
| `안뒤축감아치기` | BigThrow | Standard | `HabitCatalogue.cs:46` (H2) |
| `견제 발기술` | Poke | Sloppy | `HabitBrainCommitSource.cs:174` — Poke 라 `JudgementScored` 안 남, 이 표에 안 옴 |

### 2.2 스크립트 경로(대조 모드)에서 실명이 나오는 것 — m14 계열만

| TechniqueId | Cost | 출처 |
|---|---|---|
| `밭다리` | BigThrow | m14 제목 분해 |
| `발목받치기` | Poke | m14 제목 분해 — Poke 라 `JudgementScored` 안 남 |
| `허리후리기` | BigThrow | m14 제목 분해 |

### 2.3 참고 — 노드 id 폴백 (실명 아님, 대조 모드 전용)

m10·m11·m17·m18·m27·m33·m34·m36 은 제목이 기술을 1개만 이름 붙이거나 아예 안 붙여서
`ScriptedAssembler.TechniqueSequence` 가 이름 나열로 안 보고, `TechniqueSpec.Id` 로
**노드 id 그 자체**가 들어간다(4단계 (a) 덤프 §2.3 확인 사실). 즉 이 8개 노드의
`TechniqueId` 는 `"m10"`, `"m11"`, … 처럼 나온다 — 실제 기술명이 아니다.

이 표(§1)의 각 행에 채울 `TechniqueId` 는 **play mode(브레인 경로)에서 나올 실명**을
쓸지, **대조 모드 노드 id**를 그대로 키로 쓸지 사람이 정해야 한다. 어느 쪽으로 정하든
`ResultNarrationTable` 은 두 값 다 받을 수 있다 (그냥 문자열 키다) — 다만 하나의
국면에 두 키를 다 등록해야 대조 모드와 play mode 양쪽에서 서술이 나온다.

## 3. 등록 예시 (문구를 채운 뒤 사람이 코드에 추가할 형태)

```csharp
table.Add(Judgement.Ippon, "m36", isCounter: false,
    "체력 보정 없이도 한판은 난다 — 한판은 지치게 해서가 아니라 '읽어서' 만드는 것.");
```

빈 테이블일 때는 `ResultNarrationTable.Narrate` 가 `"{TechniqueId} — {판정명}"` 폴백을
내고 `IsFallback=true` 를 세운다 (예: `"m36 — 한판"`). 표를 채우기 전까지는 전부
이 폴백으로 보인다 — 정상이다.
